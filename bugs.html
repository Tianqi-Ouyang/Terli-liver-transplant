S1 create_table_one() → pvalue(); introduced in Adverse event docs/results.qmd commit 71a88fb (2026-04-13), copied into the shared pipeline 2026-04-14 table1::table1(..., overall = "Overall", extra.col = list("P-value" = pvalue)) passes the Overall column into pvalue() as an extra stratum (element named overall, table1 1.4.3) Every HTML p-value is computed on (group A, group B, Overall): inflated p-values, and Kruskal-Wallis instead of Mann-Whitney for 2-group continuous variables. The tableone CSV written by the same call is correct. Example: this project sex_male 0.239 vs 0.121; AlcHep scr_admit 0.431 (site) vs 0.195 (CSV) Fixed in the shared pipeline 2026-09-15 — create_table_one() is now tableone-only (CreateTableOne() → CSV, returns knitr::kable() of the same matrix; new caption = argument; warns when a variable is not in data). Sites that still show the old p-values until re-rendered: AlcHep (2 tables), Xing (1 table), Other Vasoconstrictors (1 table, never rendered). Adverse event keeps its own copy of the buggy function in docs/results.qmd (9 tables) — must be fixed there separately. Not affected: Cardio (own tableone-only override), main Terlipressin Tables.Rmd / docs/data_summary.qmd Uses the fixed shared function directly (no local override)
S2 mean-map + derived-variables chunks The master xlsx already contains mean_map_day0 (written by Tables.Rmd); the pipeline merges a second copy → mean_map_day0.x / mean_map_day0.y, no plain mean_map_day0, although CLAUDE.md lists it as provided Any all_vars entry mean_map_day0 / map_day0 is silently removed by intersect(all_vars, names(data)) Fixed in the shared pipeline 2026-09-15 — the xlsx copy is dropped before the merge (select(-any_of("mean_map_day0"))), so master$mean_map_day0 exists again (values identical to the xlsx). Xing still lists "map_day0" (wrong name) → its Table 1 row stays missing until renamed to mean_map_day0; the new create_table_one() warning now reports it map_day0_avg still computed here because it also applies the S3 recode
S3 Master data map_terli_day0_time0..3 (and therefore both copies of mean_map_day0) 0 is used as a “not measured” placeholder (25 / 4 / 2 / 2 readings); Tables.Rmd and the pipeline average it as a real pressure Day-0 MAP mean biased downward for ~30 patients Xing recodes 0 → NA and takes the median (map_terli_day0). Not handled in the main project, Cardio, AlcHep, Adverse event, Other Vasoconstrictors 0 → NA before averaging
S4 REDCap export column map_terli_time1_day1 Mis-named field (should be map_terli_day1_time1), so starts_with("map_terli_day") in the pipeline never sees it Day-1 MAP mean uses 3 readings instead of 4 (does not affect day 0) Not handled anywhere Not used in this project; noted
S5 Terlipressin git repo The create_table_one section of shared_pipeline.qmd and the matching CLAUDE.md edits are uncommitted (working copy 2026-04-14; last commit d2d94f5 2026-04-13 does not contain them).
